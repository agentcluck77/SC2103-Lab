# uP16 Processor

## Overview

The **uP16** is a simplified 16-bit educational processor designed to demonstrate pipelining and datapath concepts. It implements a basic **5-stage pipeline** without data forwarding, and is targeted at the Artix-7 FPGA (Basys 3 board) for Lab 4 of SC2103.

Key characteristics:
- 16-bit data width
- 16-bit Program Counter (PC)
- 5-stage pipeline: IF → ID → EX → Mem → WB
- No data forwarding
- No interrupt handling
- No explicit jump instructions
- No byte-level memory access (full-word only)
- All arithmetic is **signed**

---

## Program Counter (PC)

- 16 bits wide, holds the address of the **next instruction** to fetch
- Increments by **1** after each instruction (not by bytes — the IM is word-addressed)
- Resets to **0** on reset

---

## Register File

The uP16 has **8 general-purpose registers**, R0 to R7:

| Register | Special Role | Behaviour |
|----------|-------------|-----------|
| R0 | Zero register | Always reads as 0; writes are ignored |
| R1–R5 | General purpose | Normal read/write |
| R6 | Stack Pointer (SP) | Convention only — no hardware enforcement |
| R7 | Return Address (RA) | Convention only — used during function calls |

- **Reads are combinational** (immediate, no clock needed)
- **Writes are sequential** (occur on the clock edge at the end of the Mem stage)

---

## Memory Architecture

Two separate memory blocks, both implemented as **Block RAM (BRAM) macros** (not IP Core Wizard):

### Instruction Memory (IM)
- Size: **1024 × 18-bit**, single-port ROM
- Stores all program instructions
- Initialised at synthesis time via `.INIT` and `.INITP` parameters in `Instruct_mem.v`
- The 18 bits are split: 16 data bits (`.INIT_00` to `.INIT_3F`) + 2 parity bits (`.INITP_00` to `.INITP_07`) used as extra address bits to form 18-bit words
- Addressed by the PC; output is registered (1-cycle latency)

### Data/Stack Memory (DM)
- Size: **1024 × 16-bit**, single-port RAM
- Used for `lw`/`sw` instructions and stack operations
- Synchronous write (data appears on `Data_out` one cycle after the write command)

---

## Instruction Format

All instructions are **18-bit words** using a single **R-format**:

```
[17:14]  OpCode   (4 bits)
[13:11]  Rd       (3 bits) — destination / first source register
[10:8]   Rs       (3 bits) — second source register
[7:0]    Funct / Immed (8 bits) — function code or immediate value
```

Each instruction is represented as **5 hex digits** in the assembler (e.g. `00108` = `add r1, r0`).

---

## Instruction Set

### Arithmetic & Logic (OpCode = 0x00, distinguished by Funct field)

| Instruction | Funct | Effect |
|-------------|-------|--------|
| `nop` | 0x00 | Do nothing |
| `add rd, rs` | 0x01 | RF[rd] = RF[rd] + RF[rs] |
| `sub rd, rs` | 0x02 | RF[rd] = RF[rd] - RF[rs] |
| `and rd, rs` | 0x03 | RF[rd] = RF[rd] AND RF[rs] |
| `or rd, rs` | 0x04 | RF[rd] = RF[rd] OR RF[rs] |
| `nand rd, rs` | 0x05 | RF[rd] = RF[rd] NAND RF[rs] |
| `nor rd, rs` | 0x06 | RF[rd] = RF[rd] NOR RF[rs] |
| `xor rd, rs` | 0x07 | RF[rd] = RF[rd] XOR RF[rs] |
| `not rd, rs` | 0x08 | RF[rd] = NOT RF[rs] |
| `mov rd, rs` | 0x0A | RF[rd] = RF[rs] |

### Immediate Operations

| Instruction | OpCode | Effect |
|-------------|--------|--------|
| `lli rd, immed` | 0x03 | RF[rd] = sign_extend(immed) — rs unused |
| `lui rd, rs, immed` | 0x04 | RF[rd] = {immed, RF[rs][7:0]} |
| `addi rd, rs, immed` | 0x05 | RF[rd] = RF[rs] + sign_extend(immed) |

**Note on `lli`:** The 8-bit immediate is **sign-extended** to 16 bits. So `lli r3, 0xFF` stores `0xFFFF`, not `0x00FF`.

### Memory Access

| Instruction | OpCode | Effect |
|-------------|--------|--------|
| `lw rd, rs, immed` | 0x01 | RF[rd] = Memory[RF[rs] + immed] |
| `sw rd, rs, immed` | 0x02 | Memory[RF[rs] + immed] = RF[rd] |

### Branch Instructions

| Instruction | OpCode | Effect |
|-------------|--------|--------|
| `beq rd, rs, immed` | 0x08 | If RF[rd] == RF[rs]: PC += sign_extend(immed) + 1 |
| `bne rd, rs, immed` | 0x09 | If RF[rd] != RF[rs]: PC += sign_extend(immed) + 1 |
| `blt rd, rs, immed` | 0x0A | If RF[rd] < RF[rs]: PC += sign_extend(immed) + 1 |
| `bgt rd, rs, immed` | 0x0B | If RF[rd] > RF[rs]: PC += sign_extend(immed) + 1 |

- There are **no explicit jump instructions** — all control flow is done via branches
- Branch offset is relative: `PC = PC + sign_extend(immed) + 1`
- OpCodes 0x6–0x7 and 0xC–0xF are **reserved**

## Datapath & Control Signals

Three key mux control signals (from the Control module in `ID_stage.v`):

| Signal | Name | Function |
|--------|------|----------|
| S1 | `sel_PC` | Selects next PC: PC+1 (normal) or branch target |
| S2 | `sel_ALUSrc1` | Selects ALU input 2: register value or sign-extended immediate |
| S3 | `sel_Mem2Reg` | Selects writeback data: ALU result or memory data (for `lw`) |

Additional control signals:
- `RFwriteEnab` — enables write to the register file
- `memWriteEnab` — enables write to Data Memory (`sw`)
- `memEnab` — enables Data Memory access (`lw` or `sw`)
- `EX_ALUOp[3:0]` — selects ALU operation

## Pipeline Timing Summary

For any instruction fetched at cycle N:

| Cycle | Stage | What happens |
|-------|-------|-------------|
| N | IF | Instruction fetched from IM |
| N+1 | ID | Decoded; registers read; sign-extend computed |
| N+2 | EX | ALU executes; memory control signals generated |
| N+3 | Mem | Memory read/write; data available |
| N+4 | WB | Result written to register file |

Memory control signals (**bypass** the EX/Mem pipeline register), so they are active at **N+2**, not N+3.

---

## Key Limitation: No Data Forwarding

Because there is no forwarding, a **RAW (Read After Write) hazard** occurs whenever an instruction reads a register that the immediately preceding instruction is writing. The register file will not have the new value yet at the time of the read (ID stage), causing the stale old value to be used.

See `pipeline_stages.md` for a full explanation with cycle diagrams.
